## 1. Project Name and Purpose

**NeuroMotion AI** — A gesture-based stroke rehabilitation web application.

Patients use their webcam to perform prescribed upper-limb exercises while a browser-side AI model (MediaPipe PoseLandmarker) tracks their arm in real time. A 2-DOF kinematic model (shoulder → elbow → wrist) maps pose landmarks to joint angles, scores movement quality, and stores session metrics in a database. Therapists can monitor assigned patients' progress and adjust their difficulty level.

Academic alignment: covers **Unit 1** (Vectors, Matrices, Rigid Body Transformations, HTM) and **Unit 2** (D-H Parameters, Forward Kinematics, Inverse Kinematics) and **Unit 3** (Jacobian, Velocity Analysis, Manipulability).

## 4. Database and Deployment Setup

### Database

| Environment | Database |
|---|---|
| Production | **Neon PostgreSQL** via `DATABASE_URL` environment variable |
| Local development | **SQLite** (`backend/rehab_system.db`) — auto-fallback when `DATABASE_URL` is unset |

**Neon connection hardening in `backend/config.py`:**
- Normalizes `postgres://` → `postgresql+psycopg://`
- Strips `channel_binding=require` for driver compatibility
- Appends `connect_timeout=10` to fail fast on cold Neon endpoints
- `pool_pre_ping=True` — drops stale idle connections before use
- Startup DB errors are caught and logged; the service stays alive and `/api/health` reports `database: unavailable`

**Tables are created on startup** via `db.create_all()`. Exercises are seeded once via `seed_exercises()` (skips if table already has rows).

### Deployment

| Item | Detail |
|---|---|
| Platform | **Render** (both services declared in `render.yaml`) |
| Backend service | `neuromotion-backend` — Python web service, free plan |

| Backend build | `pip install -r backend/requirements.txt` |
| Frontend build | `npm install && npm run build` → publishes `dist/` |

**Environment variables that MUST be set manually in Render dashboard:**

## 5. Authentication

- **Mechanism:** Flask-Login server-side sessions + HTTP-only session cookie
- **Password hashing:** bcrypt (Flask-Bcrypt)
- **Cookie policy:**
  - Production: `SameSite=None; Secure` (required for cross-subdomain `.onrender.com` cookies)
  - Local: `SameSite=Lax`
- **Two roles:** `patient` and `therapist` — stored in `users.role`
- **Frontend guard:** `ProtectedRoute.jsx` wraps every protected route; accepts `allowedRoles` prop
- **AuthContext:** `src/context/AuthContext.jsx` — checks `/api/auth/me` on mount; exposes `login`, `logout`, `register`, `checkAuth`
- **After registration:** immediately calls `login()` and redirects to the appropriate dashboard
- **No JWT tokens, no refresh tokens, no OAuth**
- **No password reset / forgot-password flow** (not implemented)
- **No email verification** (not implemented)

## 7. Current Exercise System

**12 exercises** seeded from `backend/services/exercise_programs.py`:

| Level | # | Category | Speed | Target Radius |
|---|---|---|---|---|
| Basic (1) | 4 | ROM | Slow | 9–10 cm |
| Moderate (2) | 4 | ROM + Coordination | Normal | 5–6 cm |
| High (3) | 4 | Speed + Precision | Fast | 3–3.5 cm |

**Exercise attributes per record:**
`name`, `description`, `category`, `level`, `level_name`, `target_positions` (JSON: x/y/hold_sec/optional time_limit), `duration_seconds`, `instructions`, `suitable_stroke_types` (JSON list), `min_severity`, `max_severity`, `icon_name`, `target_radius`, `speed_requirement`

**Level unlocking rules** (in `get_exercise_program()`):
- Severity 1 → Level 1 only
- Severity 2–3 → Level 1–2
- Severity 4–5 → All levels
- Hemorrhagic stroke caps at Level 2 unless severity = 5
- Brainstem stroke caps at Level 2 unless severity ≥ 4

**Daily plan:** Up to 4 exercises selected deterministically by day-of-year rotation (same patient + same date = same plan). Completion is inferred from existing session records — no separate table needed.

## 10. Known Issues and Technical Debt

### Bug-level issues

| Severity | Location | Issue |
|---|---|---|
| 🔴 High | `ExerciseRunnerPage.jsx:498` | `avg_accuracy_score` sent to backend is the `score` state variable which **defaults to 100 and is never updated**. Real IK-based accuracy is never computed on the frontend. All sessions are saved with accuracy ≈ 100%. |
| 🔴 High | `ExerciseRunnerPage.jsx:500` | `total_targets` sent as `targetsHit + 1` — an approximation. If a patient hits 0 targets, `total_targets = 1`. Actual target count should come from `exercise.target_positions.length`. |
| 🟡 Medium | `backend/routes/auth.py:66` | `datetime.utcnow()` is deprecated since Python 3.12. Should use `datetime.now(timezone.utc)`. |
| 🟡 Medium | `backend/routes/sessions.py:77` | Same `datetime.utcnow()` deprecation. |
| 🟡 Medium | `backend/routes/exercises.py:28`, `sessions.py:112` | `Exercise.query.get_or_404()` and `User.query.get()` are deprecated in SQLAlchemy 2.x. Should use `db.session.get()`. |
| 🟡 Medium | `backend/services/gamification.py:126-128` | Double `if "rom_milestone_90" not in existing_badges` — redundant nested check. |

### Missing features (not a bug, just not built)

- No therapist ↔ patient **assignment** UI or API endpoint. The `assigned_therapist_id` foreign key exists in the DB schema but no route or UI page sets it. Therapists see zero patients unless the DB is manually edited.
- No **password reset** / forgot-password flow.
- No **email verification** on registration.
- No **Playwright tests** — the dependency is installed but no test files exist.

### Architecture notes

- `ExerciseRunnerPage.jsx` is **941 lines** — camera setup, MediaPipe integration, canvas drawing, target hit logic, rep counting, session timer, voice calls, and session save are all in one component. Strong refactoring candidate.
- `report_generator.py` is rule-based (if/else thresholds) — despite the "AI" framing, no ML model is involved. This is intentional for the current academic scope.
- The kinematic math in `kinematics_engine.py` is correct and academically complete, but several methods (Jacobian velocity, manipulability ellipsoid, joint torques, velocity profile) are **never called from any route**. Only `compute_movement_smoothness()` is used.

## 14. Important Warnings for Future AI Agents

> Read these before making any changes to this project.

1. **Do not install MediaPipe or OpenCV on the backend.** Pose detection is intentionally browser-side. Adding server-side vision would require a separate architecture.

2. **`ExerciseRunnerPage.jsx` uses both React state and refs for the same logical values** (e.g., `repCountRef` + `setRepCount`). This is intentional — the ref is read in the `requestAnimationFrame` loop (closure captures stale state), and the state triggers a re-render. Do not replace refs with state in the detection loop; it will break.

3. **Tailwind CSS v4 is in use.** There is no `tailwind.config.js`. Configuration is done via the `@tailwindcss/vite` plugin and CSS custom properties in `src/index.css`. Do not create a `tailwind.config.js` or install Tailwind v3 packages.

4. **Flask-Login session cookies require `SameSite=None; Secure` in production** because the frontend and backend are on different `.onrender.com` subdomains (which are cross-site per the Public Suffix List). If you move to same-domain hosting, you can relax this. Never set the cookie to `SameSite=Strict` in production or credentialed requests will silently fail with 401.

5. **`DATABASE_URL` must use the `psycopg` (v3) driver.** The config normalizes the URL to `postgresql+psycopg://`. If you add a new DB dependency, ensure psycopg v3 (`psycopg[binary]`) remains in `backend/requirements.txt`.

6. **Exercise seeding is idempotent** (`seed_exercises()` checks `Exercise.query.count() > 0`). Safe to call on every startup. If you add new exercises, you must either clear the table or write a migration — the seed function will not add them to an already-populated table.

7. **The `score` state variable in `ExerciseRunnerPage.jsx` is broken** — it defaults to 100 and is never reduced by incorrect movements. `avg_accuracy_score` sent to the backend is always ≈ 100. Fix this before using accuracy in any clinical context.

8. **`total_targets` in the session POST is `targetsHit + 1`**, not the actual count from the exercise definition. The correct value is `exercise.target_positions.length`.

9. **There is no therapist-patient assignment endpoint.** Any feature that relies on `assigned_therapist_id` (e.g., the therapist dashboard patient list) will show empty results unless you first implement the assignment API and UI.

10. **Render free tier spins down after 15 minutes of inactivity.** The first request after wake-up will be slow (~30s). This is expected. Neon also closes idle connections, handled by `pool_pre_ping`.

11. **`Project_status.md` was originally created as an empty file at the project root** — it is not a directory. Do not confuse it with the `PROJECT_STATUS.md` directory artifact that appeared in earlier inspection notes.
